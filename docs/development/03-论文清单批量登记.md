# 3. 论文清单批量登记：待登记目录、移动归档与配置更新

更新日期：2026-10-17。适用环境：Linux、Bash、已有 Conda `fiona`。本教程说明已实现的登记流程，不代表结构解析或切块已经完成。当前进度见 [README](../../README.md)。

## 1. 目标与目录分工

收集新论文时放入 `data/raw/unregistered/`。运行登记脚本后，符合条件的 PDF 被移到 `data/raw/registered/`，同时加入 `configs/pdf_files.json`。成功后保留空的 `unregistered/` 目录，下一批论文继续放进去。

```text
data/raw/
  unregistered/    # 未登记；日常只扫描这里
  registered/      # 已登记；登记脚本不递归扫描这里
```

输入是待登记 PDF 和已有映射，输出是更新的映射及移动后的文件。目录名不进入文档 ID，但会进入配置的相对路径。原始 PDF 字节、文件名和已有文档 ID 保持不变。

脚本只登记 `.pdf` / `.PDF`，不执行 OCR、解析、切块或重命名。非 PDF 留在待登记目录并逐项提示；冲突或失败时文件也会保留。因此“目录为空”以本批全部文件都是可成功登记的 PDF 为前提，不通过删除文件强行清空目录。

## 2. 命名、路径与状态

命名约定见[项目开发文档第 6.1 节](../../项目开发文档.md#61-论文语料准备与来源登记)。新 ID 是文件名去掉最后一个扩展名，保留完整标题、大小写及空格。例如：

```json
{
  "NIPS-2017-Attention Is All You Need": "registered/NIPS-2017-Attention Is All You Need.pdf"
}
```

`parse_pdf.py` 用 `data/raw/` 拼接映射值，实际读取 `data/raw/registered/NIPS-2017-Attention Is All You Need.pdf`。因此无需修改解析器的输入逻辑。

支持待登记目录中的子目录。例如 `unregistered/traffic/Paper.pdf` 成功后为 `registered/traffic/Paper.pdf`，ID 为 `Paper`。移完后删除空的待登记子目录，但始终保留 `unregistered/` 根目录。

目录表示登记状态，不表示解析状态。已登记文件不一定已经解析，也不保证 PDF 内部格式有效。扩展名检查不是文件内容检查。

## 3. 前置条件

在服务器终端进入项目并检查解释器：

```bash
cd /data2/wangjiaji/Fiona
conda activate fiona
python -c "import sys, fiona; print(sys.executable); print(fiona.__file__)"
```

解释器应属于 `fiona` 环境，本项目导入路径应指向 `src/fiona/`。首次安装见[环境教程](../../1.环境搭建.md)。无需增加依赖或重写锁文件。

将论文复制或下载到 `data/raw/unregistered/`；不要放入 raw 根目录或直接放入 registered，脚本不会扫描这两个位置。文件名中的会议、年份与完整标题需要提前核对，登记脚本不推断这些信息。

raw 根目录必须存在。两个子目录缺失时，正式执行会创建它们；预览不创建任何目录。目录必须是真实目录，符号链接会报错。

## 5. 实现原理与失败边界

### 5.1 仅扫描新文件

通过 `unregistered.rglob("*")` 收集待登记文件。读入已有配置用于 ID 查重，但不递归遍历 registered，也不逐个检查已有文件是否缺失。这样日常文件扫描量取决于本批文件数量；配置 JSON 仍需整体读取和保存。

所有 PDF 在移动前统一校验：ID 重复、大小写冲突、已有映射占用路径、目标文件已存在、符号链接、坏 JSON 或重复 JSON 键都会使整批失败，不部分覆盖已有条目。即使新放入的 PDF 与已登记文件内容相同，也作为冲突提示，不自动删除或合并。

### 5.2 移动与提交

预检保留配置原字节，执行前再次比较；配置在此期间改变时中止。每个文件使用 `os.link(source, target)` 排他创建目标，再移除原路径，实现同文件系统内不覆盖目标的移动；两个目录必须在同一文件系统并支持硬链接。PDF 内容不会重新写入。

全部移动成功后，配置写入同目录临时文件，再替换正式 JSON。普通移动失败、目标晚到冲突或配置写入失败时，按相反顺序将本批已移动文件放回待登记目录。已有配置在提交前保持不变；若回滚本身失败，错误中列出需要恢复的路径。

### 5.3 空目录与中断

待登记目录为空属于正常状态：返回 0，不改写配置，不读取已登记 PDF。没有配置且没有待登记文件时，不创建空 JSON，只准备两个目录。

本操作不是数据库事务：进程被强制杀死、服务器断电或其他进程同时改写文件时，不能保证目录与配置同时提交。捕获到的异常会尝试回滚；强制中断需按第 9 节核对。不要在登记过程中同时运行另一个登记任务或手工编辑配置。文件系统、权限及磁盘错误不会通过删除 PDF 绕过。

## 6. 日常命令与参数

先把论文放到 `data/raw/unregistered/`，然后执行：

```bash
python scripts/update_pdf_files.py --dry-run
python scripts/update_pdf_files.py
```

第一条只展示计划移动路径，不移动、不写配置、不创建目录。第二条执行登记与移动。摘要显示本批 PDF 数、配置总数及保留的非 PDF 数。处理成功后可以直接打开 unregistered，确认目录仍存在且本批 PDF 已移走。

|参数|含义|
|---|---|
|`--raw-dir`|根目录，内部固定使用 `unregistered/` 与 `registered/`；默认项目 `data/raw/`|
|`--config`|输出配置，默认项目 `configs/pdf_files.json`，不能位于 raw 内或是符号链接|
|`--dry-run`|只计算计划，不移动文件或写入任何产物|

显式相对路径以当前终端目录解释，默认路径以脚本所在项目解释。隔离演练时同时指定另一个 raw 根目录和临时配置；不要将实验目录的映射写入正式配置。

```bash
python scripts/update_pdf_files.py --raw-dir /tmp/fiona-trial/raw --config /tmp/fiona-trial/pdf_files.json --dry-run
```

此示例要求提前准备 `/tmp/fiona-trial/raw/unregistered/`。现有解析脚本仍固定从项目 raw 读取，其他根目录的配置不能直接用于正式解析。

退出码：成功、空目录或预览为 0；配置、目录、冲突、移动或写入错误为 2。非 PDF 保留属于提示，不使登记失败。

## 7. 与解析衔接及验证方法

配置生成后，带空格的 ID 必须加引号。使用临时输出隔离解析验证：

```bash
FIONA_PARSE_CHECK_DIR="$(mktemp -d /tmp/fiona-parse-check.XXXXXX)"
python scripts/parse_pdf.py \
  --doc-id "CIKM-2023-STAEformer - Spatio-Temporal Adaptive Embedding Makes Vanilla Transformer SOTA for Traffic Forecasting" \
  --output-dir "$FIONA_PARSE_CHECK_DIR"
```

该文件预计输出 5 条页面记录。临时目录由用户核对后清理；省略输出参数将写入正式 `data/parsed/`，成功重跑会替换同 ID 结果。登记仅改变原文存放路径，ID 保持不变，已有解析产物不用因目录移动而改名。

运行测试：

```bash
conda run -n fiona python -m unittest discover -s tests -p 'test_catalog.py' -v
```

测试使用临时占位文件检验移动与配置行为，不冒充真实 PDF 解析。内容保护核对可以独立运行：

```bash
python - <<'PY'
import hashlib
import json
from pathlib import Path

mapping = json.loads(Path('configs/pdf_files.json').read_text(encoding='utf-8'))
records = json.loads(Path('docs/catalog/2026-10-17-paper-renames.json').read_text(encoding='utf-8'))['records']
for item in records:
    path = Path('data/raw') / mapping[item['doc_id']]
    assert path.name == item['new_name']
    assert path.stem == item['doc_id']
    assert hashlib.sha256(path.read_bytes()).hexdigest() == item['sha256']
print(f'PASS：本批 {len(records)} 份文件名称、ID 与内容一致')
PY
```

这一手工核验会读取已登记 PDF，但日常登记脚本不会执行它。哈希一致只能证明文件字节未变，不能证明正文、表格或公式解析正确。

## 9. 排错、迁移与恢复

|现象|检查与处理|
|---|---|
|放入文件却提示 0 份|确认放在 `raw/unregistered/`，不是 raw 根或 registered；确认扩展名为 PDF|
|ID 已存在或目标已存在|核对是否重复下载或不同版本；保留原文件，人工决定更换 ID 或移走重复候选，脚本不覆盖|
|非 PDF 留在待登记目录|这是有意保留，移到合适的位置；PDF 配置不能登记任意格式|
|移动失败|检查两个目录权限、是否同文件系统及硬链接支持；普通异常会移回本批已移动文件|
|配置写入失败|检查配置父目录写权限；检查本批文件已回到 unregistered，再修复并重试|
|错误提示部分文件无法移回|按错误中列出的源/目标路径恢复；不要用目录清空命令处理|
|强制中断后配置与目录不一致|暂停登记，逐项对照配置与两个目录；配置没有条目但文件已移入 registered 时，将该文件移回 unregistered 后重试；配置和目标均存在则保留已登记文件，先核对可能残留的源文件，不盲删|

首次目录迁移已完成。迁移前配置及 SHA-256 保存在 `data/maintenance/2026-10-17-raw-layout/`。恢复目录布局必须同时恢复对应配置，不能仅替换 JSON。更早的文件命名备份在 `data/maintenance/2026-10-17-paper-renaming/`；它不适用于当前目录布局的单独恢复。

命名记录保留最初的原名、新文件名、完整原始标题及发表依据。文件名按 `会议或期刊简称-年份-完整标题.pdf`，冒号改为 ` -`、问号移除、排版长横线改为 `-`。STAEformer 和 SpatialRank 的年份均核对为 2023；未确认正式渠道的 LaDe 和 ST-Transformer 使用 arXiv 首次提交年。本次只调整目录，没有重新命名论文或改写其内容。

完成后，应能区分“文件已登记”“PDF 已解析”和“解析质量已核对”。继续见 [PDF 解析教程](02-PDF解析.md)与 [README](../../README.md)；下一步先完善结构解析，再切块。
